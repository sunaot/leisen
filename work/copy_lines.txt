# Option A
A-1 [H1] Google DriveもSlackも、本人の権限のまま横断検索。
A-2 [Sub] 社内ナレッジをLLMで検索できるようにするOSS基盤。アクセス可否は元のデータソースが検索する本人の資格情報で判断し、すべてのツール呼び出しを監査ログに記録します。
A-3 [バー] OSS(Apache-2.0予定)/ 認可は本人の資格情報でデータソースに委譲 / 全ツール呼び出しを監査ログに記録 / 1デプロイ=1社
A-4 [見出し] AI検索の導入でつまずくのは、検索ではなく権限です
A-5 [見出し] 権限を複製しない。可否の判断は、元のデータソースに任せる。
A-6 [見出し] 誰が・どのソースに・何を検索したか。全件、監査ログに残る。
A-7 [見出し] 回答には必ず出典リンク。原文までワンクリック。
A-8 [見出し] 導入1件の構成は、deployment.yaml 1枚。
A-9 [見出し] ソフトウェアはOSSで無償。導入支援とサポートが有償。
A-10 [クロージング] いまの環境のソースと権限構成から、一緒に確認します。
A-11 [CTA] 導入相談を申し込む / GitHubで見る

# Option B
B-1 [H1] 自社環境で動かす、OSSの社内ナレッジ検索基盤。
B-2 [Sub] Gateway・コネクタ・検索層まで、コードと設定スキーマを公開。データは自社環境から出しません。Apache-2.0(予定)。
B-3 [バー] OSS(Apache-2.0予定)/ 認可は本人の資格情報でデータソースに委譲 / 全ツール呼び出しを監査ログに記録 / 1デプロイ=1社
B-4 [見出し] 検索のたびに、ソースのAPIを本人の資格情報で呼ぶ。
B-5 [見出し] アクセス可否の判断は、元のデータソースが行う。
B-6 [見出し] 対応ソースと設定項目は、コードで確認できる。
B-7 [見出し] deployment.yaml 1枚が、導入1件のすべて。
B-8 [見出し] 全ツール呼び出しが監査ログに残る。抜け道は作らない。
B-9 [見出し] ソフトウェアはOSSで無償。導入支援とサポートが有償。
B-10 [クロージング] コードから読み始めてください。導入の相談はいつでも。
B-11 [CTA] GitHubで見る / 導入相談を申し込む

C-5 [見出し] 回答には必ず出典リンク。原文までワンクリック。
