# 02 Position

## Real difference (from brief, checked against research)
ブリーフの主張を研究セットと突き合わせた結果、実質的な差分は次の4点:

1. **認可の非複製**: 認可判定を常にデータソース側が本人資格情報に対して行う(ACL複製・同期をしない)。研究セットで同型の主張は credal(R-credal-40 "Permissions inherited at the source")と dashworks(R-dashworks-40 複製vs live)のみ。国内勢は「閲覧権限継承」(R-neuron-41)までで、判定主体には触れない
2. **データが自社から出ない**: OSSシングルテナント自社導入。本文・インデックス・監査ログのすべて。Ring Aの国内向け製品でこれを構造的に約束できるものはセット内に無い(onyxは英語圏のみ)。Ring D の D-5「クラウドを経由する事実は変わらない」・D-11「国内完結」に直接答える
3. **検証可能性**: 全ツール呼び出しの監査ログ+カナリア文書による常時検証。**セット17LPのどれも訴求していない**(反論マップの buyer-only 行)。権限恐怖(D-1〜4)の裏面「守れていることをどう確認するか」に答える唯一の候補
4. **OSS+導入伴走の組合せ**: 国内買い手の伴走欲求(R-hf-42、D-9)にOSS(価格透明・D-6)で答える組合せはセット内に空白

結論: 差分は material。メッセージ軸は differentiate が正当化される。

## Allowed deviations (closed list)
1. **FVの実績バッジ→OSS証明への置換**: シェア/導入数バッジ(R-qs-6, R-neuron-6)の位置に、GitHubリポジトリ導線・ライセンス・スター枠を置く(Line 3 の R-onyx-6, R-n8n-6 で観測済みの型の移植)。理由: 導入実績ゼロで実績訴求は偽装になる
2. **メッセージ主役の統制化**: 見出し・主要セクションの主語を「権限・データ所在・検証」にする(Line 4 の R-credal-40, R-mm-40/41, R-dashworks-40, R-gem-40 から借用)。理由: Real difference 1-3
3. **「監査ログ・カナリア文書」セクションの新設**: セットに存在しないセクション種。理由: buyer-only ギャップ(反論マップ)への直接回答。導入形: 国内型FAQ/仕組みセクションの文法で書き、異物感を抑える
4. **インストール/デプロイ具体の表示**: R-onyx-41(curlワンライナー)型の「導入1件=deployment.yaml 1枚」の具体物提示。理由: 可動部品最小・運用負荷ギャップ(D-12,13)への視覚的回答
5. **実績系プルーフのプレースホルダ化**: ロゴ帯・数値事例は `[ ]` プレースホルダとし、偽装しない。理由: ブリーフ制約(実績なし)
6. **contrast構文の許可**: 6/17で観測(R-dashworks-40, R-gl-40/41, R-n8n-42, R-dust-40/41, R-credal-41)。「複製する検索 vs 委譲する検索」等
※このリストは closed。Phase 3/4 はここに無い逸脱を導入しない。

## Target & conversion
- Target: 数百〜数千人規模の国内企業の情報システム部門・セキュリティ責任者(稟議を書く人)。副: 評価を任されるプラットフォームエンジニア
- Conversion: **両建て**(7/17観測)— 主: GitHubで評価開始(clone/Star)。副: 導入支援・デザインパートナーの問い合わせ。国内型の「資料請求」は導入プレイブック/設計文書DLに読み替え
- Objections to answer, in order(Ring D頻度優先):
  1. 権限事故への恐怖(D-1, D-2, D-3, D-4, D-7)→ 認可委譲の仕組み+検証(逸脱3)
  2. データを外に出せない・審査が通らない(D-5, D-11)→ シングルテナント自社導入
  3. 少人数情シスで運用が回るか(D-12, D-13)→ 可動部品最小・deployment.yaml 1枚(逸脱4)
  4. 導入して定着するか・伴走はあるか(D-9)→ 導入プレイブック+支援事業
  5. 価格(D-6)→ OSS(ライセンス費なし)+支援は有償と明示
  6. 本当に見つかるか(D-8)→ LLMの反復探索の説明(promise側で扱う)
- Vocabulary(fix):
  - 使う(買い手の語彙): 「見えてはいけない情報」「丸見え」「権限」「データの所在」「自社環境」「監査」「散在」「探す時間」
  - カテゴリ認識用(メタ/サブコピーに限定): 「社内ナレッジ検索」「エンタープライズサーチ」「横断検索」
  - 開発者向けセクションのみ: 「MCP」「OSS」「deployment.yaml」「コネクタ」
  - 使わない: 「RAG」「ベクトル検索」「ナレッジマネジメント」「エンパワー」等の抽象語
