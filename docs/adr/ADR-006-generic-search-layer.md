# ADR-006: 汎用検索層モジュールと導入単位の有効化

Status: Accepted / Date: 2026-07-04

## 文脈
v1では検索層は「昇格ソース判明後に構築」だったが、複数社導入では弱いソースが会社ごとに異なるため、導入ごとの手作りは成立しない。

## 決定
検索層をコアのオプションモジュールとして汎用開発する(製品開発の前倒し)。ただし全導入は検索層OFFで開始し、有効化は当該導入の監査ログに基づく昇格判定レポート(T-014)を根拠に、deployment.yaml のコネクタ単位フラグで行う。証拠駆動ゲートは製品ロードマップから各社の導入ロードマップへ移動する。

## 詳細
- Search Backend を抽象化する。具体的なエンジン選定は検索層着手時(Q3)に実データでのPoCを行い、その時点でゼロから判断する。現時点で候補を確定・記録しない(未検討の第一印象を残すことは後の判断へのアンカリング負債になるため)
- Connector SDK に optional capability `ingest()`(全件/差分クロール、変更フィード)を追加。検索層の有効化は ingest capability 実装済みコネクタに限る(型レベル制約)
- 認可は ADR-003(post-filtering)を変更なく踏襲
- 「インデックスは deployment.yaml から常に再構築可能」を運用不変条件とし、復旧・アップグレードを単純化する
