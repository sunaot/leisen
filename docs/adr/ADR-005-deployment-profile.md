# ADR-005: Deployment Profileによる設定駆動アーキテクチャ

Status: Accepted / Date: 2026-07-04

## 文脈
複数社がそれぞれシングルテナントで導入する。個社差分の吸収手段を確定する必要がある。

## 決定
導入1件の全構成(IdPアダプタ、コネクタ有効化、コネクタごとの検索層有効化、検索バックエンド、運用パラメータ)を単一の宣言的設定 deployment.yaml で表現する。コアコードに個社分岐を入れることを禁止し、差分は設定と3つのプラグイン境界(Connector / IdP Adapter / Search Backend)でのみ吸収する。

## 帰結
- 設定スキーマはバージョン管理し、マイグレーションツールを製品に含める(T-010)
- 2社以上で再現した要件のみコア化する(「2社ルール」)。個社要件は contrib/ またはフォークで対応
- 危険設定(認可バイパスに相当する組合せ等)は起動時に拒否する
- マルチテナント機構は実装しない。1デプロイ=1社を不変条件とする

## 追補(2026-10-13): Connector プラグインの解決規則

Connector の実装は `connectors[].module` の明示か、公式コネクタの許可表(kind → パッケージ名)でだけ解決し、kind から導いたパッケージ名を暗黙に読み込まない(ADR-021)。個社のコネクタは `module` を deployment.yaml に書いて読み込む。プラグイン境界全体の見直し(IdP Adapter 等の動的読み込み)は issue #23 で別途扱う。
