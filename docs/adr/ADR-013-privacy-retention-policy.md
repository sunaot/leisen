# ADR-013: プライバシー・保持・ログ閲覧方針

Status: Proposed — 決定値ドラフト確定(2026-07-09)。情報セキュリティ・法務・労務のレビュー完了をもってAccepted化 / Date: 2026-07-05

## 文脈
本人権限検索はSlackのDM・プライベートチャンネル等を含む。認可上は正当(本人は見てよい)だが、fetchedDocIds等のメタデータが中央監査ログに全件記録されるため、管理者が「誰がいつどのDMを参照したか」を閲覧できる。監視ツール化の懸念、就業規則・労使協議、個人情報保護の論点であり、日本企業への導入では確実に問われる。また、回答に転写された機密はチャット履歴に残り、その後の権限剥奪に遡及しない。

## 決定値(ドラフト。関係者レビューで承認・修正する)

### 1. プライベートスコープの既定除外
- deployment.yaml に `connectors[].privateScopes: excluded | consent | included` を設け、**既定は `excluded`**(DM・プライベートチャンネル・個人スコープを検索対象外)
- `consent` は**本人のオプトイン同意**モード: 利用者が自分のプライベートスコープを検索対象に含めることを明示同意した場合のみ有効化する(Slackの `search:read.private` が要求する本人同意ゲートと整合)。同意は撤回可能とし、同意状態の変更を監査ログに記録する
- `included` への変更は**確認フラグ必須**(なければ起動拒否、TM-E4)+ 利用規程の整備を導入チェックリストで要求する(docs/usage-policy-template.md)

### 2. プライベートスコープdocIdの監査ログ上の扱い
- deployment.yaml に `audit.privateScopeDocIds: hashed | omitted` を設け、**既定は `hashed`**
  - `hashed`: デプロイ固有鍵によるHMACで不可逆化して記録する。同一文書の参照頻度集計(昇格判定、T-014)は可能なまま、監査閲覧者が日常的にdocIdから文書を特定できないようにする。なお鍵アクセス権限者は候補docIdからの照合が可能なため、これは暗号学的匿名化ではなく「牽制+規程(§3)との組合せ」である旨を利用規程に明記する
  - `omitted`: プライベートスコープのdocIdを記録しない(参照頻度集計は不能になる)
- 平文記録の選択肢は**提供しない**(要望が2社以上で再現した場合に再検討 — 2社ルール)
- Slack由来のdocIdは本設定に関わらず**常に不可逆化**する(ADR-014、不変条件7が優先)

### 3. 監査ログの閲覧権限・目的・保持期間
- **閲覧権限**: 導入先が指名する監査閲覧担当(指名制・ロールベース)に限定する。監査ログへのアクセス自体を記録する(メタ監査、TM-F3)。分離テレメトリ(ADR-011)はセキュリティ担当の高権限限定
- **閲覧目的の限定**(利用規程で明文化): (a) セキュリティインシデント調査、(b) 権限逸脱検出(カナリア検証を含む)、(c) 昇格判定・運用改善(T-014。集計値の利用を原則とする)、(d) 法令・社内規程に基づく正式な調査。**目的外利用(人事評価・日常的な行動監視への転用)を禁止**する
- **保持期間の既定値**(いずれもdeployment.yamlで変更可):
  - AnswerRun / ToolInvocation(2層監査ログ本体): **365日**
  - rawQueryテーブル: **30日**(ADR-011の短期保持)
  - 分離テレメトリ(post-filter品質): **14日**
  - 期限超過分の削除を定期ジョブで実施し、削除実行も記録する

### 4. チャット履歴の保持・エクスポート・共有
- 保持期間はdeployment.yamlで設定し、**既定は90日**。期限超過分は削除する(T-009でテスト必須)
- **エクスポート機能・共有機能は実装しない**(禁止を明記。将来の追加はADR必須)
- Slackソースを含む回答は既定で永続履歴に残さない(残す場合はSlack由来部分をredact/不可逆化 — ADR-014、T-009)
- 回答に転写された機密が権限剥奪に遡及しない問題は、保持期間の短さ+エクスポート・共有禁止で影響範囲を限定する(構造的解決はスコープ外として受容し、利用規程に開示する)

## 帰結
- T-001(監査スキーマ): `privateScopeDocIds` の hashed/omitted 処理、保持期間の設定注入、メタ監査を要件化
- T-010(設定スキーマ): `privateScopes`(既定excluded)、`audit.privateScopeDocIds`(既定hashed)、`audit.retentionDays`(既定365)、`audit.rawQueryRetentionDays`(既定30)、`chatHistory.retentionDays`(既定90)、`privateScopes: included` の確認フラグ検証
- T-009(チャットUI): 履歴保持既定90日・エクスポート/共有非実装・Slack由来非永続
- 導入プレイブック: 利用規程テンプレート(docs/usage-policy-template.md)を標準工程に組み込む。`consent`/`included` を使う導入では労使協議・就業規則の整合確認を人間タスクとする
