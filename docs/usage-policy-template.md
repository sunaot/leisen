# 利用規程テンプレート(骨子)— 社内ナレッジ検索基盤

Status: 確定(2026-07-12、ADR-013のAccepted化に伴う。T-000b成果物)/ Date: 2026-07-09

本書は導入プレイブックの一部として各導入先が自社の規程に落とし込むためのテンプレート骨子である。
`< >` は導入先が埋める箇所。ADR-013 の決定値を既定として記載しており、既定から変更する場合は
deployment.yaml の設定と本規程の記載を一致させること(不一致は監査上の指摘事項とする)。

---

## 1. 目的・適用範囲

- 本規程は、社内ナレッジ検索基盤(以下「本システム」)の利用、および本システムが記録する
  監査ログ・チャット履歴の取り扱いを定める
- 適用対象: <全従業員 / 対象部門> および本システムの運用担当者・監査閲覧担当者
- 本システムは利用者本人のアクセス権限の範囲でのみデータソースを検索する(権限透過)。
  本システムを経由しても、利用者が本来アクセスできない情報にはアクセスできない

## 2. 検索対象と除外(プライベートスコープ)

- 検索対象のデータソース一覧: <deployment.yaml の connectors に一致させる>
- DM・プライベートチャンネル等のプライベートスコープの扱い: <excluded(既定)/ consent / included>
  - `excluded`(既定): プライベートスコープは検索対象外
  - `consent`: 利用者本人が明示同意した場合のみ、その利用者の検索に本人のプライベートスコープを
    含める。同意はいつでも撤回できる。同意・撤回の操作は記録される
    (注: 同意状態の持ち方が未設計(#42)のため、現在の版では `consent` を指定すると起動を拒否する。
    ADR-016 追補2 決定6)
  - `included`: <採用する場合、労使協議・就業規則との整合確認の実施記録をここに参照として残す>

## 3. 監査ログ

### 3.1 記録される情報
- 全ツール呼び出しについて: 利用者ID、日時、対象ソース、クエリのダイジェスト、認可済み返却件数、
  取得した文書ID、最終回答の引用文書、利用者フィードバック(ADR-011の2層モデル)
- 記録されない情報: 認可されていない候補の内容・件数(ADR-012)、トークン等の秘密情報、
  Slack由来の本文・メタデータ(ADR-014)
- プライベートスコープの文書IDの扱い: <hashed(既定・HMACで秘匿化して記録)/ omitted(記録しない)>。
  `hashed` は暗号学的匿名化ではなく、閲覧担当者が日常的に文書を特定できないための牽制であり、
  監視への転用を技術的に防止するものではない。本規程の目的限定(3.3)と組み合わせて機能する。
  Slack由来の文書IDは設定に関わらず記録されない(ADR-013/ADR-014)
- 検索クエリの原文は<30日(既定)>で削除される短期テーブルに分離して保持される

### 3.2 閲覧権限
- 監査ログを閲覧できる者: <指名された監査閲覧担当者の役職・氏名/ロール>(指名制)
- 監査ログへのアクセスはすべて記録される(メタ監査)
- 分離テレメトリ(検索品質の集約統計)の閲覧: <セキュリティ担当の高権限者>

### 3.3 閲覧目的の限定
監査ログの閲覧は次の目的に限る。**目的外利用(人事評価・日常的な行動監視への転用を含む)を禁止する**。

1. セキュリティインシデントの調査
2. 権限逸脱の検出(カナリア文書検証を含む)
3. 検索基盤の改善・昇格判定(原則として集計値を用いる)
4. 法令または社内規程に基づく正式な調査(<承認手続き: 例 情報セキュリティ委員会の承認>)

### 3.4 保持期間
- 監査ログ本体: <365日(既定)>
- 検索クエリ原文: <30日(既定)>
- 分離テレメトリ: <14日(既定)>
- 期限超過分は自動削除され、削除の実行が記録される

## 4. チャット履歴

- 保持期間: <90日(既定)>。期限超過分は削除される
- 履歴のエクスポート機能・他者への共有機能は提供されない
- Slackを情報源に含む回答は永続履歴に保存されない(または Slack 由来部分が不可逆化される)
- 注意事項として利用者に開示する: 回答に転写された情報は、その後に元文書へのアクセス権を
  失っても履歴の保持期間内は本人の履歴に残る

## 5. 利用者の責務

- 本システムの回答を社外・権限外の者へ共有する場合は、元文書の共有と同じ社内規程に従う
- 検索結果・回答に自分の権限では見えないはずの情報が含まれていた場合は、直ちに
  <報告窓口> へ報告する(権限逸脱インシデント)
- 文書内の不審な指示テキスト(プロンプトインジェクションの疑い)を発見した場合は
  <報告窓口> へ報告する

## 6. アカウント・権限の変更時の取り扱い

- 退職・異動等でIdPのアカウントが無効化されると、本システムの各データソースへの接続
  (保管されたトークン)は失効処理される
- データソース側での権限剥奪が本システムの検索結果に反映されるまでの遅延は最大
  <認可キャッシュTTL: 例 15分>(設定値と一致させる)
