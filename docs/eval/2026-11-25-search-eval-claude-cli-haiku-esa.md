# 比較実験(条件 3・4)の実測: claude -p(haiku)、esa 型(2026-11-25)

T-027 の `dev-search-eval` による計測。条件 3(利用者の発言を探索 LLM に渡す)と条件 4(UI 側 LLM が作った `question` を探索 LLM に渡す)を、`claude -p` を LLM に使って実行した。条件 1・2 は `docs/eval/2026-11-25-search-eval-conditions-1-2.md` の esa 型の値を再掲する。

## 実行条件

### 最初の実行(応答の形式の説明を直す前)

同じ条件で一度実行したが、その結果は採らなかった。応答の形式の説明(`CLAUDE_CLI_RESPONSE_PROTOCOL`)が「ツールを直接呼び出す仕組みがない」と書いていたため、モデルが `claude -p` の中で `submit_answer` や `fetch` を関数として直接呼ぼうとして CLI から「No such tool available」を受け、回答を JSON の `text` に書いて終える(Orchestrator は提出として扱わず unresolved にする)試行が多かった。条件 3 の答えられる質問で「全件引用」は v3 7 / 17、v4 11 / 17 だった。UI 側 LLM が `ask` を呼ばなかった試行も v4 で 5 件あった。説明を「`<tools>` のツールはすべて使える。関数として直接呼ばず、JSON の tool_calls に書く。提出も tool_calls で行う」に直して再実行したのが上の結果である。直した後も、CLI の内部で 3 ターン以上かかった呼び出し(直接呼ぼうとした目安)は v3 で 120 / 189 回、v4 で 95 / 205 回あった。

## 解釈

- 条件 2(発言を直接)は esa 型で 0 / 17 だが、条件 3 では v3・v4 とも 17 / 17 の質問で正解が 10 位以内に返った。この質問セットと esa 型の模擬では、探索 LLM がクエリを書くことによる損失は、人が書いたキーワード(条件 1)と比べて recall@10 ではほとんど見えない。差が出たのは順位で、v3 は名詞 1 語の検索が多く、recall@1 が条件 1 の 71% より低い(35%)
- v4 は v3 より上位に正解を返し(recall@1 35% → 82%)、fetch してから引用する割合が高い。一方で search の回数は約 2 倍になり、費用は 1 試行あたり約 1.4 倍だった。各 1 回の試行なので、この差がばらつきの範囲を超えるかは分からない
- 条件 3 と 4 の差は、この計測では UI 側 LLM の言い換えの影響ではなく、探索 LLM の試行ごとのばらつきと、LLM の呼び出しの失敗による。UI 側 LLM(haiku、簡易な再現)は発言を変えなかった
- 答えられない質問はすべて棄権したが、そこに至るまでに 9〜16 回の search を使っている。上限に達するまで検索を続ける傾向がある
- 構造化出力による模擬は、CLI の内部でモデルが関数呼び出しを試みることがあり(上の「最初の実行」)、応答の形式の説明の書き方で結果が大きく変わった。この結果を Anthropic API のネイティブのツール呼び出しでの結果とみなすことはできない

## 限界

- 各組み合わせ 1 回の試行で、ばらつきは測っていない(`--repeat` 2 以上で測る)
- 合成コーパスと、開発用コネクタによる模擬の検索方式(esa 型)での結果。実際の esa の挙動との一致は未確認(T-029)
- LLM は `claude -p` の構造化出力によるツール呼び出しの模擬。strict のツール定義・思考の要求・キャッシュのブレークポイント・`max_tokens` は効かず、CLI 自身の内部の指示(ログイン中の利用者の情報などの少量の文脈を含む)と構造化出力の仕組みが間に入る。応答の形式の説明は Orchestrator のプロンプトの外にあり、その文面で結果が変わることを確かめた
- 条件 4 の UI 側 LLM は簡易な再現で、LibreChat が UI 側の LLM に渡すシステムプロンプトは再現していない。LibreChat の既定の小型モデルでもない
- 質問セットは v4 の文面を書いた後に別の担当が作ったものとされており、T-024 の事前固定の条件(v4 より前に固定した質問で評価する)を満たすかは要確認。コミットの時刻は質問セット(`ec0f148`、2026-11-25 19:55 UTC)が v4 のプロンプト(`44667e2`、20:04 UTC)より前だが、文面を書いた時点との前後はコミットからは分からない
- 価格表(`config.ts`)に `claude-haiku-5-5` がないため、Orchestrator の費用の概算は「不明」になり、回答の warnings にその旨が出る。費用は CLI の `total_cost_usd` で数えた
- トレース(JSONL)はリポジトリに入れていない。作業時の置き場所はセッションの一時ディレクトリ(`claude-cli-eval/` の `full-v3.jsonl`・`full-v4.jsonl`、最初の実行は `run1-*.jsonl`)で、消えることがある
