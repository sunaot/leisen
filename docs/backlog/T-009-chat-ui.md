# T-009: 非永続フロントエンド(Slack 対応の一時チャット UI)

**2026-10-09 に要件を付け替えた(issue #21、オーナー決定)。** 元の「チャット UI(最小)」は ADR-018 により LibreChat で充足したため(下の「更新(2026-09-28)」)、本タスクは「会話を永続化しないフロントエンド」として再定義する。元の内容・受け入れ条件は履歴として残す。

## 付け替え後の内容(2026-10-09)
目的: Slack ソース(不変条件 7、ADR-014)を検索対象に含める導入向けに、会話をサーバー側に保存しない利用面を用意する。LibreChat とは並存し、Slack を有効にした導入だけがこちらを使う(ADR-018 決定 5 の起動時拒否と `--allow-non-persistable-sources` の規約はそのまま)。

- 会話をサーバー側に保存しない。状態はブラウザのメモリだけに置き、リロード・タブを閉じると消える。サーバー側に DB・ファイルの保存先を持たない
- `ask` の `structuredContent.retentionClass` を読み、`non_persistable` の回答には「この回答は保存・コピーしない」旨の表示を付ける。エクスポート・共有・ブラウザ保存(`localStorage` 等)の機能は実装しない(禁止を明記。将来の追加は ADR 必須)
- 認証は同じ Keycloak の本人トークンを Orchestrator(`leisen-ask serve`)へ転送する(ADR-018 決定 8 と同じ規約。UI は独自の資格情報を持たない)
- `leisen-ask serve` 側に「UI が非永続であることの申告」を受ける口は作らない。UI の自己申告は信頼できないため、決定 5 の起動時拒否と解除フラグの意味を変えない
- 出典リンク(出典欄の url のみ、本文の URL は描画しない)、解決 / 未解決のフィードバック(`feedback` ツール)は元の要件を引き継ぐ
- 時期: Slack コネクタ(T-006)の着手が決まってから。それまでは本定義の保持のみ(導入形態の法務確認は 2026-10-13 に類型(a)で決着、#59)

## 付け替え後の受け入れ条件(2026-10-09)
- [ ] サーバー側プロセスが会話の内容を書き出さない(ファイル・DB・ログ)ことがテストされている
- [ ] 未ログイン時にいかなるツール呼び出しも発生しない
- [ ] `retentionClass: non_persistable` の回答に非保存の表示が付き、エクスポート・共有・ブラウザ保存の経路がない
- [ ] 出典リンクがクリックで原典に遷移し、本文の URL は描画されない
- [ ] フィードバックが `feedback` ツール経由で本人の run だけを更新する

## 元の内容(2026-09-28 まで。履歴)

## 内容
- SSO(IdP)ログイン、ストリーミング表示、出典リンク、解決/未解決フィードバックボタンの最小UI
- **初回接続同意の導線(ADR-010)**: 未接続ソースがある場合の接続促しとOAuth同意フローへの誘導
- **チャット履歴の保持ポリシー(ADR-013決定値)**: 保持期間は `chatHistory.retentionDays`(既定90日)で設定可能化、エクスポート/共有機能は実装しない(禁止を明記。将来の追加はADR必須)
- **Slack由来回答の扱い(ADR-014、不変条件7)**: Slackソースを含む回答は、Slackの固有名詞・要約・permalinkを含みうるため、(a) 通常のチャット履歴に永続化しない(エフェメラル/短期保持)か、(b) 履歴に残す場合はSlack由来部分をredact/不可逆化する。出典permalinkの保存可否も同方針に従う。既定は非永続とし、永続化を選ぶ場合はToS/RTS規約上の許容性を法務確認する(T-013)
- フィードバックは監査ログ(AnswerRun)のoutcome更新APIに接続

## 受け入れ条件
- [ ] 未ログイン時にいかなるツール呼び出しも発生しない
- [ ] 出典リンクがクリックで原典に遷移する
- [ ] 履歴の保持期間がdeployment.yamlから注入され、期限超過分が削除されることがテストされている
- [ ] Slackソースを含む回答が既定で永続履歴に残らない(または残す場合Slack由来部分がredactされる)ことがテストされている

## 更新(2026-09-28): 汎用チャット UI での充足(ADR-018、T-021)
自前の UI は作らず、Orchestrator を MCP サーバーとして公開して LibreChat をつなぐ(ADR-018)。本タスクの要件のうち、LibreChat の overlay で満たすもの・委ねるものを分ける:
- 未ログイン時にツール呼び出しが起きない: Orchestrator サービスが Bearer を Gateway で確かめてから run を始めるため満たす(T-021 受け入れ条件1)
- 出典リンク: `ask` の出典欄(url は http/https のみ)で満たす
- 履歴の保持期間: LibreChat の `interface.retentionMode` / `generalChatRetention` に委ねる(deployment.yaml からの注入はしない。docs/ui-librechat.md に設定を記す)
- Slack を含む回答の非永続: Orchestrator サービスは Slack kind が有効な構成では起動しない(ADR-018 決定5)。解除は明示フラグと法務確認(ADR-014)
- 初回接続同意の導線(ADR-010)とフィードバックボタンの自動連携は未対応(T-021 残課題、T-004 以降)
