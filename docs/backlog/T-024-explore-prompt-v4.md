# T-024: 探索プロンプト v4(複数文書の質問の分解と、見つからないときの打ち切り)

## 依存
T-007(Orchestrator)、T-022(v3 の汎化確認。改訂の根拠は `docs/eval/2026-10-09-t022-generalization.md` §4・§5)

## 前提(人手)
- 実走には LLM が要る(オーナーの手元の LM Studio。v3 の計測と同じモデルを基準にする)
- 新しい質問の書き手を決める(下記「判断が必要な点」)

## 背景
v3 は 20 問 × 2 回で 37 / 40 合格した。不合格の 3 件はすべて複数文書の質問で、原因は、質問を事柄ごとの検索に分解できていないこと。2 つ目の事柄が質問文に明示されていないと届かず、見つけたヒットを読まずに打ち切ることもあった。また、文書にない質問は正しく unresolved になるが、上限(6 ターン)まで探し続け、所要時間が全種類で最も長い(中央値 77.8 秒)。

T-022 の 20 問は v4 の改訂の材料になるため、v4 の効きの評価には使えない(回帰の確認には使う)。

## 内容
- **新しい質問を先に固定する。** v4 のプロンプトを書く前に、別のコミットで新しい質問を `examples/eval/` に足す(既存の 20 問とは別ファイルにするか、種類に「held-out」を表す印を付けて区別する)。複数文書の質問を中心にし、文書にない質問と、1 文書の質問(表記ゆれ・英語を含む)も入れる
  - 複数文書の質問は、2 つ目の事柄が明示されているものと、明示されていない(質問から推して探す)ものの両方を入れる
  - 必要なら合成コーパス(`examples/fixtures/dev-corpus.yaml`)に文書を足す。足した文書も質問と同じコミットで固定する
- **`prompts/explore.v4.md`** を追加し、`EXPLORE_PROMPT_VERSION` を `explore.v4` に上げる。v3 から引き継ぐ防御の文言(インジェクション・URL・出典)はテストで固定したまま残す。改訂の候補:
  - 複数の事柄を聞く質問は、事柄ごとに分けて検索する(並行に呼んでよい)。1 つの事柄の文書が見つかった後も、残りの事柄を探す。見つかったヒットは fetch してから判断する
  - 見つからないときの打ち切り: 1 語の検索・区画を絞った検索がいずれも 0 件なら、上限まで探さずに unresolved で答える。早く打ち切ると表記ゆれの立て直しを損なうおそれがあるため、回帰で確かめる
- **v3 との比較の手段**: 同じ質問を v3 と v4 で流す。v3 のコミットで dev-eval を流すか、開発用にプロンプトの版を指定する手段(本番では使えないもの)を足す
- 評価レポートを `docs/eval/` に書く(v3 と v4 の比較、種類別、Gateway の監査から読んだ呼び出し順、不合格の原因の分類)

## 受け入れ条件
- [ ] 新しい質問が、v4 のプロンプトより前のコミットで固定されている(履歴で順序を確かめられる。計測後に質問・期待値を差し替えない)
- [ ] 新しい質問には、複数文書の質問(2 つ目の事柄が明示されているもの・いないものを各 2 問以上)、文書にない質問(2 問以上)、1 文書の質問(表記ゆれ・英語を含む 2 問以上)がある
- [ ] `prompts/explore.v4.md` と版の更新があり、v3 から引き継ぐ防御の文言と v4 で足した方針の文言がテストで固定されている
- [ ] 新しい質問で v3 と v4 を `--repeat 2` で比べた結果がレポートにある(合否、種類別、ターン数、所要時間)
- [ ] T-022 の 20 問で v4 を `--repeat 2` で流し、回帰がないことを確かめている(特に表記ゆれ・英語の合格と、文書にない質問で作り話をしないこと)
- [ ] 文書にない質問のターン数・所要時間の変化を報告している
- [ ] v4 が v3 より良くならない場合は v3 のままにし、採用しない判断とその根拠をレポートに残す

## 判断が必要な点
- **新しい質問の書き手**: A: オーナー / B: v4 を書かない別のセッション・人が書き、計測前に固定する / C: v4 を書くセッション(T-022 と同じ手当てで)。v4 の改訂者が書くと、改訂で直る形の質問に寄りやすい
- **打ち切りを入れるか**: 所要時間の短縮と、表記ゆれの立て直しの損失の兼ね合い。計測の結果を見て決める(入れない判断もありうる)
- **合格ライン**: ここでは決めない(#20 の「最低ラインの置き場所」と T-008 で決める)

## 限界
- 合成コーパスと開発用コネクタ(AND の部分一致)での評価。実ソースでの効きは T-025 / T-019 の実疎通後に別途測る
- 1 モデル(LM Studio)での計測。Claude API は資格情報が用意されてから(ADR-017。モデル系統ごとにプロンプトの派生を置いてよい)
