# T-027: Orchestrator のランタイムとエージェント定義の分離(ADR-026 決定 1〜7)

## 依存
T-007(Orchestrator)、T-023(Gateway の run API)

## 前提(人手)
- ADR-026 が Accepted になっていること(現在は Proposed。「人間に確認してほしい点」1〜5・7 への回答)
- 実走は要らない(脚本テストとモック API サーバーで確かめる)

## 背景
LLM に渡す文言が 5 か所に分かれており、`EXPLORE_PROMPT_VERSION` はその一部しか指していない。版の切り替えにはコードの編集が要り、導入企業が動作を固定する手段もない(ADR-026「文脈」)。

用語(エージェント定義、ランタイム)は ADR-026「用語」の定義に従う。

## 内容
- **エージェント定義の形式と読み込み**(決定 2・4): 形式のスキーマ(zod)、内容全体から計算するハッシュ、`packages/orchestrator/definitions/` への配置。`prompts/` は廃止する
- **現在の v3 の移行**(決定 4): system prompt の固定部、制御メッセージ、ツールの説明、`submit_answer` の説明、ループの上限を、LLM に渡る内容が変わらない形でエージェント定義に移す。Gateway の説明に `USAGE_HINTS` を連結している部分は、連結後の文字列をエージェント定義の側に持つ
- **ランタイムの整理**(決定 3): `Orchestrator` の `systemPrompt` オプションを、エージェント定義を受け取るオプションに置き換える。ランタイムに固定する処理(run API の申告、利用者の照合、データの前置き、出典の検証、無害化、上限の強制)は、エージェント定義から変更できないことをテストで固定する
- **ループの上限の解決**(決定 2): `deployment.yaml` の値を上限とし、エージェント定義の値がそれを超える場合は `deployment.yaml` の値を使う
- **既定と固定**(決定 5): `deployment.yaml` の `orchestrator.agents.search.definition`(`default` または `<名前>@sha256:<ハッシュ>`)。既定の対応表(モデルの系統 → エージェント定義)。起動を拒否する 4 つの場合。起動ログに識別子を 1 行出す
- **取り下げの一覧**(決定 6)
- **AnswerRun への記録**(決定 7): `POST /runs` の本文、`answerRunRecordSchema` の `agentDefinition`、過去のレコードを `null` として読む互換
- **文書**: `packages/orchestrator/README.md` の「プロンプトの変更」を改める。運用者向けに、固定が保証する範囲(エージェント定義の同一性だけ)を `docs/install.md` に書く

## 受け入れ条件
- [ ] 移行後の v3 で、LLM に渡る要求(system・最初の user ターン・ツール定義・制御メッセージ)が移行前と一致することをテストで確かめている。文言を固定している既存のテストが通る
- [ ] エージェント定義だけを変えても、出典の検証・無害化・データの前置き・利用者の照合・上限の強制を無効にできないことがテストされている
- [ ] エージェント定義のループの上限が `deployment.yaml` の値を超える場合に、`deployment.yaml` の値が使われることがテストされている
- [ ] `definition` の指定が、名前の不一致・ハッシュの不一致・形式のバージョンの非対応・取り下げ済みのいずれかの場合に、起動を固定文言で拒否する(既定に切り替えない)ことがテストされている
- [ ] 実行環境の CLI(`leisen-ask`、`leisen-ask serve`)に、同梱されていないエージェント定義を読み込む手段がない
- [ ] AnswerRun に `agentDefinition` が記録され、この項目を持たない過去の監査ログを昇格判定レポートが読める
- [ ] `npm run lint:imports` が通る(`packages/audit` の import 境界を変えない)
- [ ] security-reviewer のレビューを受けている(監査スキーマと設定検証の変更)

## 判断が必要な点
- ADR-026「人間に確認してほしい点」1(データの前置きの文言の置き場所)、2(effort)、4(どの系統にも当てはまらないモデルの扱い)、5(`agentDefinition` を申告のままにするか)
- **モデルの系統の判定方法**: プロバイダとモデル ID の前方一致で決める案を既定とする。OpenAI 互換のローカルのモデルは判定できないことが多い

## 限界
- 探索ループの本体(`orchestrator.ts`)で制御メッセージを出す箇所は、ADR の起案時には検索で確認しただけである。着手時に全体を読んで洗い出す
- 加工のエージェント、導入企業が自作したエージェント定義、エージェント定義へのコードの追加は扱わない(ADR-026 決定 9)
