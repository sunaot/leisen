# T-022: dev-eval の質問セット拡充と再現性の計測(探索プロンプト v3 の汎化確認)

## 依存
T-007(Orchestrator)、dev-eval(PR #43)。T-008(評価ハーネス + 評価セット v0)の前段

## 前提(人手)
- 実走には LLM が要る(オーナーの手元の LM Studio。2026-10-08 の計測と同じモデルを基準にする)
- 質問は計測の前に固定する(下記「判断が必要な点」)

## 背景
探索プロンプト v3 は、合成コーパスの 4 問で見えた失敗(言い換えを 1 つの query に並べて 0 件、list の空の結果を「文書がない」と誤読)を見て作った改訂で、同じ 4 問で 4 / 4 合格した(`docs/eval/2026-10-08-explore-v3.md`)。この 4 問への合わせ込みを否定できないため、v3 を作る前に見ていない質問と、同じ質問を繰り返したときのぶれで確かめる。

## 内容
- 質問セット `examples/eval/dev-questions.json` に質問を足す(既存 4 問の ID は変えない)。合成コーパス(`examples/fixtures/dev-corpus.yaml`)のうち、まだ質問のない 4 文書(onboarding-guide / meeting-bodies / leave-request / wiki-writing-guide)を含め、次の種類を揃える
  - 未カバーの文書を正解とする質問
  - 表記ゆれ: 文書と違う言い回し・略語・別名(例: 有給 / 年休、リモート接続 / VPN)
  - 英語の質問(日本語の文書を引けるか)
  - 複数の文書にまたがる質問(正解が 2 文書以上)
  - 文書にない質問(unresolved を期待。作り話をしないか)
- dev-eval の拡張
  - 複数文書の質問のために、期待した文書をすべて引用したかの判定(例: `citeAllOf`)を足す
  - 質問に種類のタグを持たせ、種類ごとの合格数を集計する
  - `--repeat` のとき、質問ごとの合格回数(n 回中 k 回)を表と集計に出す
- 計測: v3 で `--repeat 2` を流し、`docs/eval/` に新しいレポートを書く。不合格は Gateway の監査(ツールの呼び出し順・ヒット件数)から原因を分類する(検索語の作り方 / 区画の探し方 / fetch しない / 断定)

## 受け入れ条件
- [ ] 質問セットに、未カバーの 4 文書それぞれを正解とする質問が 1 問以上ある
- [ ] 表記ゆれ・英語・複数文書・文書にない質問が、それぞれ 2 問以上ある(合計 15 問程度以上)
- [ ] dev-eval が「期待した文書をすべて引用したか」・種類ごとの集計・`--repeat` 時の質問ごとの合格回数を出し、それぞれユニットテストがある
- [ ] 質問の追加が計測より前にコミットされている(計測後に質問を差し替えていないことを履歴で確かめられる)
- [ ] v3 で `--repeat 2` の結果をレポートにし、不合格の原因を分類している
- [ ] 結果を見てプロンプトを再改訂する場合は、改訂後に、その改訂の前に見ていない質問でも測る(同じ合わせ込みを繰り返さない)

## 判断が必要な点
- **質問の書き手**: **決定(2026-10-09、オーナー): C(v3 を書いたセッションが書く)。** 選択肢は A: オーナー / B: 別のセッション・人 / C: v3 を書いたセッション(手早いが、v3 の弱点を避けた質問になりうる)。C の弱点への手当て: 利用者が普段使いそうな言い回しで書き、文書と語が一致しない質問(表記ゆれ・英語)と文書にない語を含む質問を意図して入れる。質問は dev-eval の拡張と別のコミットで、計測より前に固定する。評価レポートには書き手が C であることを明記する
- **合格ライン**: 何割の合格で v3 を良しとするかは、ここでは決めない(#20 の「最低ラインの置き場所」と T-008 で決める)

## 限界
- 合成コーパスは 7 文書で、開発用コネクタの検索は AND の部分一致だけ。実ソース(GitHub 等)での効きは T-019 の実疎通後に別途測る
- 1 モデル(LM Studio)での計測。Claude API は資格情報が用意されてから
