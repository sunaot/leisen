# T-000c: 脅威モデル【実装前ゲート】

## 目的
実装前に攻撃面を列挙し、テスト設計(T-008、T-013のセキュリティスイート)の入力を作る。

## 内容
以下を対象にSTRIDE等の枠組みで脅威モデルを書く(docs/threat-model.md):
- 未認可候補の流出経路(ADR-012の境界の裏取り: ログ、メトリクス、エラーメッセージ、タイミング)
- existence leak(件数・挙動差からの存在推定)
- トークン漏洩(Token Vault、メモリ、ログ)と権限剥奪の反映遅延(認可キャッシュTTL)
- プロンプトインジェクション経由の情報引き出し(検索対象文書内の指示テキスト、出典リンク・画像URL経由のexfiltration)
- 管理者の誤設定(deployment.yamlの危険な組合せ)
- 監査ログ自体への攻撃(改竄、欠落、閲覧権限)
- ユーザー間キャッシュ共有・describe/カタログの共有コンテキスト化

## 受け入れ条件
- [ ] 各脅威に対策・検出手段・対応タスクIDが紐づいている
- [ ] カナリア文書の設計(配置ソース、検証周期、アラート経路)が含まれる
- [ ] T-008の評価シード(権限境界・インジェクション・存在しない情報)に反映されている
