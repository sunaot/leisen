# T-008: 評価ハーネスと評価セットv0

## 前提(人手)
社内の実クエリサンプル(まず20〜30問、正解文書付き)の提供。**権限プロファイルを固定したテストアイデンティティ**(一般社員相当/部門限定相当など複数)のIdP・各ソースでの整備。

## 内容
- 評価セット(質問、正解文書ID、質問タイプタグ、**実行アイデンティティ**)のスキーマとリポジトリ内管理(機密クエリの扱いは別途判断)。正解は実行者の権限に依存するため、アイデンティティごとに期待値を持てる構造にする
- **レッドチームシードを含める**(`docs/threat-model.md` §6 の RS-1〜RS-6 を正とする): RS-1 権限境界(見えてはいけない文書が引用されないこと)、RS-2 存在推定(existence leak)、RS-3/RS-4 プロンプトインジェクション(指示追従・exfiltration)、RS-5 存在しない情報、RS-6 古い情報。RS-1/RS-2 は合否判定、RS-3〜6 は率で追跡
- ハーネス: Orchestratorに評価セットを流し、解決率・引用正確性・ツール呼び出し回数・レイテンシ・コストを計測、前回結果と比較レポートを出力
- **Slack由来の評価(ADR-014)**: Slackの documentId は channel:ts / permalink 由来でありそれ自体がメタデータのため、production workspaceに対してはcontent/metadataを評価ログ・成果物に保存しない(非内容メトリクスとカナリア非出現のみ記録)。再現性のある内容評価は synthetic Slack workspace で行い、正解IDもそちらで管理する
- CIには含めず、手動/定期実行(コスト管理)

## 受け入れ条件
- [ ] 同一設定で2回実行した際の指標ぶれが報告に含まれる(分散の可視化)
- [ ] 権限境界テストで「権限外文書の引用ゼロ」が合否判定される
- [ ] プロンプト変更PRに評価レポートを添付するワークフローがREADME化されている
