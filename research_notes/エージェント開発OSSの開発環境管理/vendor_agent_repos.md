## 1. Which context files exist (root and nested), how long are they, and what do they contain?

### Takeaway
Almost every active project commits a root context file plus a handful of short nested ones placed next to the code they govern; root files are 5–240 lines (not thousands) and consist of build/test commands, architecture maps, style rules, and explicit "never" lists. The two notable exceptions are openai/codex (root `AGENTS.md` deleted on 2026-09-30; only four tiny nested files remain, and `CLAUDE.md`/`.claude/` are gitignored) and aider (no context file at all).

### Inferences
- Nested files are short and local; they state a contract or a single pitfall for one directory. Root files concentrate on things an agent cannot infer from code: commands with "when not to run" guidance, default branch, release tooling not used, and prohibited git/CI actions.
- Three single-source patterns coexist for multi-tool compatibility: symlinks (zed: `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` → `.rules`; cline: `.claude/skills/*` → `.agents/skills/*`), import stubs (goose: `CLAUDE.md` = `@AGENTS.md`), and vendor-only (gemini-cli: `GEMINI.md` only).
- Projects are moving detailed, area-specific knowledge out of the root file into skills (OpenHands, gemini-cli, zed, cline) and keeping the root file as an index plus invariants.
- Vendors mostly use only their own tool's file name in their own repo (GEMINI.md for Gemini CLI, CLAUDE.md for Anthropic repos), but several vendor repos carry competitors' files (cline has `.claude/` and `.codex/`; goose and zed carry `CLAUDE.md`; codex gitignores `CLAUDE.md`/`.claude/`).

### Gaps
- The content of codex's deleted root `AGENTS.md` and `.codex/skills/` was not read (shallow clone; only the deletion PR and history page were checked). Secondary blogs describe the pre-deletion file as a Rust-workspace-specific guide ([example](https://codex.danielvaughan.com/2026/05/03/anatomy-production-agents-md-openai-codex-repository-case-study/)) — unverified here.
- Amp's own product repository is not public; how Amp's team structures its internal AGENTS.md is unknown. A third-party blog calls Amp proprietary ([source](https://codex.danielvaughan.com/2026/04/07/sourcegraph-amp-multi-repo-orchestrator/)) — unverified against a Sourcegraph statement.
- Nested-file contents were sampled, not read exhaustively (opencode's 17, software-agent-sdk's 7).

## 2. Do they commit tool directories (.claude/, .codex/, .gemini/, .opencode/, .cursor/ …) with commands, agents, skills, hooks — or gitignore them?

### Takeaway
Most projects commit a curated, shared subset of their own tool's directory (commands, skills, a few subagents, minimal settings/hooks) and gitignore the personal/local parts with allow-list patterns. Skills are now the dominant committed artifact; committed hooks are rare and trivial (formatter, cloud setup, on-stop check). Codex is the outlier: nothing tool-specific remains in the public tree.

## 6. Stated policies about what goes in the public repo and about agent-generated contributions

### Takeaway
Policies cluster around three ideas: (1) issue-first with maintainer approval before any PR (or no external PRs at all), (2) humans must understand and personally write the human-facing text, and (3) agents working in the repo must obey the committed context file. Several projects also state explicitly what must not be persisted in the repo (scratch plans, temporary PR artifacts).

### Cited Findings
- **codex**: external PRs not accepted; contributions limited to issues, reproduction, root-cause analysis and design discussion — [docs/contributing.md](https://github.com/openai/codex/blob/HEAD/docs/contributing.md)
- **zed** "AI Policy": "we expect a human in the loop who genuinely understands the work an LLM produces"; "we don't accept contributions from autonomous agents"; "Don't rely on LLMs to write the whole thing for you when communicating with the maintainers"; shared LLM chat context must be quoted and disclosed as AI-generated; adapted from ripgrep's AI policy — [CONTRIBUTING.md](https://github.com/zed-industries/zed/blob/HEAD/CONTRIBUTING.md)
- **pi-mono**: "You must understand your code."; "Using AI to write code is fine. Submitting AI-generated slop without understanding it is not."; "If you use an agent, run it from the `pi` root directory so it picks up `AGENTS.md` automatically. Your agent must follow the rules and guidelines in that file."; all issues/PRs from new contributors are auto-closed until a maintainer replies `lgtmi`/`lgtm`; accounts that "spam the tracker with agent-generated issues" are blocked — [CONTRIBUTING.md](https://github.com/earendil-works/pi-mono/blob/HEAD/CONTRIBUTING.md)
- pi-mono AGENTS.md requires AI-posted comments to end with an AI-generated disclaimer line — [AGENTS.md](https://github.com/earendil-works/pi-mono/blob/HEAD/AGENTS.md)
- **opencode**: "UI and core product features require design review before implementation"; "Long, AI-generated PR descriptions and issues may be ignored. Write a short explanation in your own words."; "Follow package-specific instructions in nearby `AGENTS.md` files"; the style guide for humans *is* the root AGENTS.md ("Follow the repository style guide" links to it) — [CONTRIBUTING.md](https://github.com/anomalyco/opencode/blob/HEAD/CONTRIBUTING.md)
- **goose**: "Please write the issue yourself. Your agent can do the research and help you explore, but you should understand the issue."; "Pull requests that do not implement a Ready issue will be closed."; AGENTS.md tells agents to "Write issue and pull request comments for humans, not as exhaustive work logs" — [CONTRIBUTING.md](https://github.com/aaif-goose/goose/blob/HEAD/CONTRIBUTING.md), [AGENTS.md](https://github.com/aaif-goose/goose/blob/HEAD/AGENTS.md)
- **gemini-cli**: "All PRs should be linked to an existing issue"; issues tagged "🔒Maintainers only" are reserved; contributors can run the same agentic PR review locally (`./scripts/review.sh <PR_NUMBER>`) — [CONTRIBUTING.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/CONTRIBUTING.md), [docs/issue-and-pr-automation.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/issue-and-pr-automation.md)
- **cline**: "All contributions must begin with a GitHub Issue" (except small fixes); "PRs without approved issues may be closed."; AGENTS.md: "Don't add `.changeset/` files or other per-PR changelog entries" — [CONTRIBUTING.md](https://github.com/cline/cline/blob/HEAD/CONTRIBUTING.md), [AGENTS.md](https://github.com/cline/cline/blob/HEAD/AGENTS.md)
- **OpenHands**: the `HUMAN:` section of PR descriptions "is reserved for human contributors only" and is validated by CI; implementor agents must treat `.agents/skills/verify-*/` as read-only ("Report a mismatch or missing coverage instead of changing the specification to match the implementation"); "Verification-skill maintenance belongs in a separate PR and a separate agent context" — [AGENTS.md](https://github.com/OpenHands/OpenHands/blob/HEAD/AGENTS.md)
- **What not to keep in the repo**: OpenHands `.pr/` is deleted at release and must not hold anything to preserve ([software-agent-sdk AGENTS.md](https://github.com/OpenHands/software-agent-sdk/blob/HEAD/AGENTS.md)); opencode: "Git history preserves removed plans and scratchpads" ([specs/v2/README.md](https://github.com/anomalyco/opencode/blob/HEAD/specs/v2/README.md)); gemini-cli/Roo/pi-mono gitignore planning directories ([gemini-cli .gitignore](https://github.com/google-gemini/gemini-cli/blob/HEAD/.gitignore), [Roo .gitignore](https://github.com/RooCodeInc/Roo-Code/blob/HEAD/.gitignore), [pi-mono .gitignore](https://github.com/earendil-works/pi-mono/blob/HEAD/.gitignore))
- **claude-code-action** CONTRIBUTING notes that on fork PRs "jobs that call Claude are skipped because forks don't get the credentials they need" — [CONTRIBUTING.md](https://github.com/anthropics/claude-code-action/blob/HEAD/CONTRIBUTING.md)
- **Project status changes**: Roo Code was shut down and its repo archived on 2026-05-15 (secondary sources; consistent with the last commit date in the clone) — [morphllm summary](https://www.morphllm.com/roo-code); continue's README states the repository "is no longer actively maintained and is read-only" — [README](https://github.com/continuedev/continue/blob/HEAD/README.md)

### Inferences
- The context file is treated as a public contract for outside contributors' agents as well as for staff: CONTRIBUTING files point to AGENTS.md as the style guide and require agents to run from the root so it loads.
- Policies protect two things from agent drift: human-authored communication (PR "HUMAN" sections, issue text) and verification assets (OpenHands' read-only verify skills, separate PR and separate agent context for changing them).
- No project states a general rule like "agent harness files are private" — the default is to commit them. The only removal of harness files from a public tree (codex) came with no stated policy.

### Gaps
- No explicit written policy was found in any repo on which agent files should or should not be public; conclusions here are drawn from practice.
- Roo Code shutdown details come from third-party sites, not from RooCodeInc's own announcement.

## 7. Proportion of agent-authored commits (publicly stated and observable)

### Takeaway
Public statements claim very high shares for the vendors' own products (Claude Code ~90% to "100%", Codex app >90%, aider's "Singularity" badge 88%), but these are self-reported. Commit metadata gives a visible lower bound that varies widely: about half of recent commits in OpenHands' SDK carry an agent co-author trailer, 5–26% in most others, and 0% in codex (the internal→public mirror strips or never had them).

### Cited Findings
- An Anthropic spokesperson said about 90% of Claude Code's code is written by Claude Code; Boris Cherny said of his own work "it has been 100% for two+ months now, I don't even make small edits by hand" (January 2026) — [Fortune](https://fortune.com/2026/01/29/100-percent-of-code-at-anthropic-and-openai-is-now-ai-written-boris-cherny-roon/)
- Secondary reports: Cherny posted in March 2026 that Claude Code is "100% written" by Claude Code — [OfficeChai](https://officechai.com/ai/claude-code-is-now-100-written-by-claude-code-creator-boris-cherny) (secondary; original post not checked)
- Secondary reports: the Codex team estimates Codex generated more than 90% of the code in its own app (Pragmatic Engineer "How Codex is built", Feb 2026; paywalled, seen only via summaries) — [mirror/summary](https://thepixelpioneers.blogspot.com/2026/02/how-codex-is-built.html) (unverified against the original)
- aider's README carries a "Singularity" badge at 88%, titled "Percentage of the new code in Aider's last release written by Aider itself" — [README](https://github.com/Aider-AI/aider/blob/HEAD/README.md)
- Observed lower bounds from commit metadata (last 500 commits on the default branch as of 2026-11-15; counted = commits whose message has a `Co-authored-by:` trailer naming an AI agent/vendor; squash merges and stripped trailers make this an undercount) — verified from `git log` of each repo:
  - OpenHands/software-agent-sdk: 254/500 (trailers: `openhands` 195, Claude 110) — [commits](https://github.com/OpenHands/software-agent-sdk/commits/main)
  - OpenHands/OpenHands: 177/500 (`openhands` 98, Claude 64) — [commits](https://github.com/OpenHands/OpenHands/commits/main)
  - continuedev/continue: 132/500 (Claude 178 trailers, Cursor 24) — [commits](https://github.com/continuedev/continue/commits/main)
  - anthropics/claude-code-action: 83/500 (Claude 109 trailers); 277/500 authored by "GitHub Actions" — [commits](https://github.com/anthropics/claude-code-action/commits/main)
  - google-gemini/gemini-cli: 67/500; 70/500 authored by `gemini-cli-robot` — [commits](https://github.com/google-gemini/gemini-cli/commits/main)
  - aider: 52/500 with `aider (<model>)` co-author trailers, plus 85/500 authored as "Paul Gauthier (aider)" — [commits](https://github.com/Aider-AI/aider/commits/main)
  - block/goose: 40/500 (Claude 37) — [commits](https://github.com/aaif-goose/goose/commits/main)

  - crush: 9/500 (Claude 10 trailers) — [commits](https://github.com/charmbracelet/crush/commits/main)

- Independent context: a RedMonk analysis of ~24K commits in H1 2026 found under 1% "inarguably written by machines" and calls that a floor because unattributed AI code is not counted — [RedMonk](https://redmonk.com/sogrady/?p=6232) (secondary; seen via search summary)

### Inferences
- Attribution practice, not actual usage, drives the visible numbers: projects whose agent adds trailers by default (OpenHands, Claude Code users, aider) look agent-heavy; projects that squash, strip, or mirror (codex, opencode, pi-mono) look near zero despite maintainers building agents with agents.
- Several vendors' repos show cross-tool usage in the trailers (Claude trailers in OpenHands, goose, zed, cline, continue, crush; Cursor trailers in cline, continue, claude-code-action), matching the multi-tool context files seen in section 1.

### Gaps
- No public statement on agent-authored share was found for opencode, cline, goose, zed, crush, gemini-cli or pi-mono.
- The trailer counts are a single 500-commit window per repo and depend on regex matching of co-author names; they were not cross-checked against PR-level attribution.
- The Pragmatic Engineer article and the original Cherny posts were not read directly.
