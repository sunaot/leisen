# Stage 3 統合分析 — leisen LP

入力: 10-pain-research/(クラスタpc-01〜pc-10)、15-market-research/(src 34件・観察129件)、pattern-matrix.csv、category-fingerprint.yaml。
本書の結論はすべて「観察に基づく仮説」であり、成果(CVR)の証拠を持たない。

## 1. ペイン側の核心

1. **買い手(情シス/DX責任者)の現在の痛みの重心は「AIを導入できるか」ではなく「統制できるか・説明できるか・定着させられるか」に移っている。** シャドーAI(pc-01, 強)と監査証跡の空白(pc-02)が最も製品適合が高く、審査側の定型3問「見えないけど大丈夫?」「勝手にされない?」「説明できる?」という外部語彙まで取れている。
2. **利用者側の痛み(探せない pc-05)は実在するが自覚が薄い。** 回避策「人に聞く」が安価なため、痛みは回答係(情シス・バックオフィス, pc-03)と組織(属人化 pc-04、ツール疲弊 pc-06)に転嫁されて初めて大きく見える。LPの入口を「検索が大変」に置くのは弱い。
3. **製品の創業問題「権限逸脱が怖くて接続できない」(pc-10)は、外部証拠上は間接的。** 単独の入口にせず、pc-01/pc-02の外部証拠と束ねて使う。
4. **正直に扱うべき限界**: 記録されていない知識(pc-04)と閉域(pc-09)には効かない。「またツールか」(KM施策7割未達の学習性無力感)は当製品自身への最大の反論。

## 2. 市場側の核心

1. **権限の語りは表層で止まっている。** 国内で「閲覧権限 継承」(Neuron)・「権限維持検索」(ChatSense)という名詞句が流通し始めたが、方式(誰の資格情報か・同期か委譲か)まで開示するLPはゼロ(ws-01)。USはGlean(言い切り)とDashworks(非インデックス差別化)のみが深い。
2. **監査可能性は未使用の差別化語彙**(ws-02)。審査3問に正面から答えるLPが存在しない。
3. **実績ゼロでも使える証明の型が存在する**: 標準準拠(Keycloak)、機構の実演(docker run)、検証可能性=ソース公開(AnythingLLM)、誠実さ・思想(Basecamp/ONCE)。ロゴ・導入社数の三層証明は当面構造的に不可能なので、これらが代替。
4. **国内の買われ方**: LP=稟議支援文書(縦長1枚完結・資料DL+デモ二段・料金/権限/FAQ内蔵)+導入伴走の明示。OSS型文法(GitHub・self-host)との併置は空白(ws-04)。
5. **「学習に使わない/データはあなたのもの/国内(自社)環境」は既に入場券。** 差別化ではなく、書かないと減点。

## 4. 差別化候補(次ステージへの引き渡し)

- **候補X「方式まで見せる権限透過」**: 検索は常に本人の権限で・ソースが判定・コードで検証可能。ws-01直撃。リスク: 技術的すぎて非エンジニア決裁者に重い。
- **候補Y「説明できるAI検索(監査・統制)」**: 審査3問に答える。全数監査・human-in-the-loop・カナリア。ws-02直撃。リスク: セキュリティ製品と誤認される可能性。
- **候補Z「置き換えない・預けない・縛らない」**: いまのツールのまま横断検索、データは自社環境、OSSで退出自由。pc-06+SaaS抵抗に応答。リスク: 消極的価値の羅列になり固有性が薄まる。
- 競合所有の物語(「自社を理解するAI」「その場所でAI」「非インデックス」)は避けるか、正面から比較軸をずらす。

## 5. 証拠の弱点(Skeptic向け自己申告)

- ペイン定量の多くがベンダー委託調査(Helpfeel/Notion)またはアナリスト引用の孫引き(ガートナー73%)。
- 対象規模(数百〜数千人)ど真ん中の一次証言が薄い。エンジニア発信に偏る。
- 広告→LP対応は両広告ライブラリ到達不能で証拠ゼロ。traffic_source想定(organic)は未検証。
- 競合LPの観察はサーバーサイド取得のため、ビジュアル・アニメーションの観察が不完全(Airbyte等はagent-readable変種)。
