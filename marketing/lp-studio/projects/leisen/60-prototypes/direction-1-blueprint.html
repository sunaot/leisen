01

許可も、禁止も、正解にならない

許可すれば

共有設定のミスひとつで、見せてはいけない情報が回答に混ざるかもしれない。「誰に何が見えるか」を、導入前に説明しきれない。

禁止すれば

利用は止まらず、把握できない場所で個人のAIに社内情報が貼り付けられていく。禁止した瞬間、報告も検知もされなくなる。

必要なのは、権限とログの規律を最初から持った「公式の経路」です — 少なくとも、AIが社内ナレッジに触れる部分については。

02

いまあるツールの上に足す、検索の基盤

Leisen(仮称)は、社内のデータソースをMCPプロトコルでつなぎ、AIが社内情報を検索・取得できるようにするゲートウェイ基盤です。ナレッジの移行も、新しい置き場所も要りません。いまあるツールは、いまのまま。

チャットからも、業務エージェントからも使えます。回答には必ず原典へのリンクが付き、ワンクリックで元の文書に戻れます。

  • Google Drive
  • Slack
  • GitHub
  • Confluence / Notion 等のwiki
  • + コネクタをプラグインとして追加
03

権限リストを、複製しないという設計

  1. 権限データベースを持たない

    ACLの複製・同期・翻訳をしません。権限のコピーは、作った瞬間から古くなります。

  2. 検索は、必ず本人の資格情報で

    AIからの検索・取得は、利用者本人の資格情報で各ツールのAPIを呼び出します。

  3. 判定するのは、元のツール

    アクセス可否は毎回、データソース自身が判定します。ソース側で権限を変えれば、それがそのまま検索にも反映されます。

導入単位の構成は、1枚の宣言的な設定ファイルで表現します。

# deployment.yaml(抜粋)
idp:
  adapter: keycloak          # okta / entra-id / keycloak
connectors:
  - id: gdrive
    enabled: true
    privateScopes: excluded  # 私的領域は既定で対象外
  - id: slack
    enabled: true            # オンデマンド検索のみ(保存しない)
audit:
  failureMode: fail-closed   # 監査に書けなければ止まる

この方式は、設計判断の記録(ADR)とコードで公開します。[placeholder: OSS公開は準備中です]

04

セキュリティ審査の観点に、設計で答える

審査でよく問われる観点と、本基盤の設計上の回答
審査の観点Leisenの設計
アクセス制御独自の権限モデルを持たず、判定は常にデータソースが本人に対して行う(権限の二重管理が発生しない)
監査証跡すべての検索・取得が単一経路(Gateway)を通り、会話単位・ツール呼び出し単位の2層で記録される
学習利用基盤自体は社内データを学習・蓄積する機構を持たない。接続するLLM側の学習ポリシーは、各社のAI契約に従う
私的領域DM・プライベートチャンネル等は既定で検索対象外(設定で明示しない限り含めない)
逸脱の検証「見えてはいけない文書が見えないこと」を継続確認するカナリア文書テストとレッドチーム項目を導入手順に同梱
人の関与自律エージェントからの利用は、既定で人の確認(human-in-the-loop)を挟む

※ 第三者認証(ISMS等)の取得は現段階ではありません。設計文書と検証手順の全文公開で答えます。

05

できないことを、先に言います

  • 記録されていない知識は探せません。誰かの頭の中にしかない情報は対象外です。検索できるのは、いまツールの中にあるものだけです。
  • DM・プライベートチャンネルは既定で検索しません。働く人の私的領域を、既定で検索対象にしない設計です。
  • Slackのデータは保存・インデックスしません。利用規約に沿ったオンデマンド検索のみです。
  • 初期構成は、速くありません。検索のたびに各ツールへ問い合わせるため、1つの質問に10〜60秒かかることがあります。権限の正しさを、速さより優先しています。
  • SaaSではありません。自社環境への導入作業が必要です(そこを支援するのが私たちの事業です)。
  • 導入実績は、まだありません。だから、最初の数社を探しています(下記のデザインパートナー募集)。
06

小さく入れて、証拠で広げる

  1. 検証 — OSSで小さく試す

    自社環境に立てて、1部門・2ソースから。ソフトウェアのライセンス費用はかかりません。

  2. 運用 — インデックスを作らずに本番へ

    フェデレーテッド検索(都度問い合わせ)で運用開始。全アクセスが監査ログに残ります。

  3. 拡張 — ログの証拠で判断する

    「どのソースで、何が解決しなかったか」のレポートを見て、ソース追加やインデックス(検索層)の有効化を判断します。勘ではなく、記録で。

導入アセスメント・構築・運用は、開発元が伴走します(有償)。

08

よくある質問

M365 Copilotと何が違いますか?

スイート内蔵AIは、そのスイート内のデータに最適化されています。Leisenは、Microsoft内外に散らばるソース(Google Drive・Slack・GitHub・wiki等)を、単一の権限規律と監査ログで横断するための基盤です。置き換えではなく併用が前提です。

検索のたびに各ツールへ問い合わせるなら、遅くないですか?

初期構成では1つの質問に10〜60秒かかることがあります。権限の正しさと導入の軽さを、応答速度より優先する設計です。速度が課題になったソースだけ、証拠(利用ログ)に基づいてインデックスを検討します。

OSSなのに、何を販売しているのですか?

ソフトウェアは公開し、導入アセスメント・構築支援・運用サポートを有償で提供します。

どのAIから使えますか?

MCPに対応したAI・エージェント(Claude等)から利用します。LLMは同梱しないため、既にお使いのAI契約をそのまま活かせます。

料金は?

OSS部分は無償です。導入支援・サポートは個別見積です。[料金体系は準備中]

いつから使えますか?

OSS公開と正式名称は準備中です。デザインパートナー企業には先行してコードと支援を提供します。
