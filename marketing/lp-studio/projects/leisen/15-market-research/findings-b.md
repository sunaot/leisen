# findings-b: 日本市場ナレッジ検索/社内AI LPの説得構造(2026-08-27観察)

対象12件(到達11件、Graffer AI Studioは本文JSレンダリングのためmetaのみ)。証拠は `source-register-b.csv` / `observations-b.jsonl`。以下はすべて「LP上で観察された主張の構造」であり、施策の成果証拠ではない(performance_support: none)。

## 1. 日本のB2B SaaS LPの型(繰り返し観察されたパターン)

1. **資料DL+デモ/問い合わせの二段オファーが標準形。** Helpfeel・Qast・exaBase・Neuronはトライアル無しの「資料ダウンロード」「デモ/お問い合わせ」構成。トライアルを前面に出すのはNotePM・ナレカン・ChatSenseの3社のみで、うちフリーミアム(¥0プラン+30秒登録)まで踏み込むのはChatSenseだけ(obs-b31)。
2. **証明の三層構造: 数値バッジ → 大企業ロゴ → 第三者アワード。** 導入社数/ユーザー数/継続率のバッジをヒーロー直下、ロゴカルーセル、ITreview・BOXIL・ITトレンドのランキングバッジという順序がほぼ共通(obs-b02, b16, b25)。米国LPに比べ第三者レビューサイトのアワードへの依存が顕著。
3. **「No.1」訴求には出典注記が付く。** exaBaseは「国内シェアNo.1(※1,2)」にデロイト系・富士キメラの出典を明記(obs-b34)。Neuronは「ITトレンド年間ランキング9年連続1位」。景表法対応込みの定型。
4. **規制産業ロゴ=間接的セキュリティ証明。** 「銀行・大学も導入」(NotePM)、官公庁・国立がん研究センター(ChatSense)、自治体・LGWAN(Neuron)。認証バッジより先にロゴで「固いところで通った」ことを示す(obs-b16, b32)。
5. **稟議支援としてのLP。** ナレカンは時間×人件費のROI試算(1,882時間/789万円)をLPに直接掲載(obs-b12)、NotePMは21段の料金表を全公開(obs-b18)、Neuronは価格帯と契約形態比較を公開(obs-b27)。縦長1枚で機能・権限・ROI・FAQを完結させ、そのまま社内説明に使える形にする傾向。
6. **導入後の定着不安への応答が独立セクション化。** Helpfeelの導入支援体制、Qastのサポート3種、Grafferの「伴走支援・研修」(metaのみ)、exaBaseの「会社に定着する」というヘッドライン(obs-b05, b34, b38)。「導入したが使われない」第一波の失敗経験が買い手の前提になっている。
7. **匿名競合比較表(A社B社C社)** はChatSenseで観察(obs-b32)。実名比較は皆無。

## 2. セキュリティ/権限/データの語られ方

- **生成AI系の必須三点セット: 「学習されない」「国内リージョン/国内サーバー」「ISMS」。** ChatSense「学習されずにAI利用」、exaBase「データ処理は国内サーバーで行われ、モデル学習への情報提供も遮断」、ナレカン「貴社の情報が外部に漏れることはございません」(obs-b30, b36, b11)。米国OSS勢はこの種の情緒的安心文言を使わず、SOC2/RBAC/audit logsの列挙で処理する(obs-b45)——日米で反論処理の文法が異なる。
- **「権限」の語られ方は3階層に分かれる:**
  1. *自社製品内の権限設定*(ナレカン: フォルダ権限・閲覧のみ・IP制限・SSO)— 大半の国内ナレッジSaaSはここ止まり(obs-b11)。
  2. *参照範囲の限定*(NotePM「NotePM上の情報だけを参照するAI。だから、安心して使える。」)— AI追加に伴う新反論への応答(obs-b17)。
  3. **既存ソースの権限継承・維持** — Neuron ESが「閲覧権限 継承」をファーストビューの3大バッジに置き(obs-b24)、ChatSenseが「権限維持検索」を機能名化して比較表の差別化軸にする(obs-b30)。Onyxは「respects fine grained access controls」(obs-b41)。
- **示唆(interpretation): 権限透過は国内LPでちょうど言語化され始めた段階。** 「閲覧権限 継承」「権限維持検索」という短い名詞句がすでに市場に流通しているが、その実装方式(誰の資格情報で照会するのか、同期か委譲か)まで開示するLPは一つも無い。ここは差別化の余白。
- FAQ/公開情報系(sAI Search、Helpfeelトップ)は権限をほぼ語らない。権限の語りの深さが、その製品が社内機密を扱う土俵にいるかどうかのリトマス紙になっている(obs-b03, b22)。

## 3. OSSと商用SaaSの説得構造の違い

| 軸 | 国内商用SaaS | OSS(Onyx/Dify/AnythingLLM) |
|---|---|---|
| 主証明 | 導入社数・第三者アワード・ISMS | GitHub stars(20k/153k/64k)・DL数・Docker pulls・コントリビュータ数 |
| ロゴ | 国内大手・規制産業 | グローバル大企業(Adobe, Merck, Mercedes等)— OSSでもロゴ戦は同じ |
| 反論処理 | 「学習されない」+国内リージョン+認証 | セルフホスト/VPC=データ主権+SOC2/RBAC/監査ログ(Onyx/Dify)、または「データがデバイスを出ない」という機構そのもの(AnythingLLM, obs-b47) |
| CTA | 資料DL+デモ(営業ファネル) | Try free / Download / GitHub(self-serve)+Book a Demo/Contact Salesの並走 |
| 価格 | 非公開〜全公開まで割れる | Cloud/Enterprise/Communityのデプロイ形態3枚カードがプラン表を兼ねる(obs-b44) |
| 独自要素 | 導入支援・伴走、セミナー導線 | Self-Host Guide、自社ベンチマーク公表(Onyx: 対ChatGPT 64% win rate)、GitHubリンクが証明とCTAの二役 |

- **OSSに「資料ダウンロード」という概念が存在しない**のが最大の構造差。ゲートは資料ではなくコード/デモ。
- Difyは Enterprise カードに「Built for procurement, security, and audit」と調達側の語彙を直書きし、OSSでありながら稟議プロセスに直接話しかける(obs-b44)。OSS→エンプラ商用化の文法として参考価値が高い。
- AnythingLLMは第三者認証ゼロでプライバシー訴求を成立させる(ソース公開=検証可能性が認証の代替、obs-b49)。ただし国内エンプラ稟議でこの論法が単独で通る観察例は無い。

## 4. 本プロジェクト(権限透過の社内ナレッジ検索OSS基盤)への含意

- 権限を語る国内LPは「自社製品内の権限設定」の列挙が主流で、**「認可をデータソースに委譲し、本人の資格情報で照会する」ことを機構レベルで説明するLPは観察範囲に存在しない**。Neuron「閲覧権限 継承」/ChatSense「権限維持検索」という既出の短い語彙に接続しつつ、機構の透明性(OSSなので検証可能)で一段深く語れる位置が空いている。
- 日本の買い手向けには、OSS型の証明(stars・セルフホスト)だけでは足りず、国内型の型(ISMS等の認証、規制産業での通過実績、稟議に転記できるROI/構成情報、導入・定着支援の明示)を併置する必要があるというのが両群の観察からの示唆。
- 監査ログは国内LPではほぼ語られず(Difyが「audit logs」を列挙する程度)、「全アクセスが監査可能」は未使用の差別化語彙。
